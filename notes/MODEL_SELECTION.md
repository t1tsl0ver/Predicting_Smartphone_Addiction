# Model selection and tuning backlog

## Train and validation metrics

Для решения о продолжении обучения важна динамика качества на данных, которые
модель не использует для подгонки:

- training metric показывает, насколько модель описывает обучающие строки;
- validation metric оценивает перенос на невидимые строки;
- рост обеих метрик означает, что явного переобучения пока не видно;
- рост training при остановке или падении validation означает переобучение.

В текущем CatBoost-логе колонка `test` — это наш локальный `eval_set`, то есть
validation, а не скрытый Kaggle test. В `trial-001` validation AUC рос до 1000-го
дерева, поэтому дальнейшее увеличение потенциально полезно. Оно отложено до
отдельного trial.

## Почему одного holdout недостаточно для большого поиска

Каждый раз, когда мы смотрим результат на одном validation и выбираем следующую
идею, мы косвенно подстраиваем решения под эти строки. Несколько ручных trial
допустимы, но Grid Search или Randomized Search сравнивают много конфигураций и
могут выбрать случайного победителя одного split.

Перед систематической оптимизацией нужно отдельно согласовать схему, например:

1. сохранить внешний holdout для единственной финальной проверки;
2. подбирать параметры на оставшихся данных через 3-fold stratified CV;
3. сравнивать средний ROC AUC и разброс между folds;
4. только выбранную конфигурацию один раз оценивать на внешнем holdout.

Kaggle leaderboard нельзя использовать вместо внешнего holdout для постоянного
подбора решений.

## Grid Search и Randomized Search

Grid Search перебирает все комбинации заданной сетки. При нескольких параметрах
число запусков быстро становится огромным. Randomized Search проверяет случайную
выборку комбинаций и обычно разумнее как первый этап для дорогого CatBoost.

Кандидаты для будущего поиска:

- `depth`;
- `learning_rate` вместе с числом `iterations`;
- `l2_leaf_reg`;
- параметры стохастичности и сэмплирования;
- возможно, параметры разбиения числовых признаков.

Сначала нужен широкий Randomized Search с небольшим бюджетом, затем узкий поиск
вокруг сильной области. Такой поиск является отдельным согласуемым trial или
серией trial, а не автоматическим следующим действием.

## Пороги и ROC AUC

Для submission в этом соревновании порог класса искать не нужно. ROC AUC принимает
вероятности и оценивает их порядок. Преобразование вероятностей в `0/1` уничтожает
часть информации и обычно ухудшает AUC.

Порог вида `probability >= 0.5` нужен для метрик и прикладных решений, где требуется
готовый класс: accuracy, precision, recall, F1 или стоимость ошибок. Пороги внутри
деревьев по значениям признаков CatBoost находит сам во время обучения.

## Итог полного CatBoost exp-006

Полный CatBoost с 3000 деревьями и `learning_rate=0.01` улучшил standalone
LightGBM `exp-003`, но проиграл rank blend `exp-005` локально и на Kaggle. Все
пять folds выбрали последнюю итерацию, поэтому plateau формально не найден.

Несмотря на это, увеличение CatBoost-бюджета сейчас имеет низкий приоритет:
модель существенно дороже LightGBM, а до принятого бленда остаётся около
`0.00098` OOF и `0.00116` leaderboard. Активный подбор возвращён к LightGBM.
Сохранённые OOF/test predictions позволяют позже проверить CatBoost как
межсемейный blend-компонент без повторного обучения.
