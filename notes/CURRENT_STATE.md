# Current state

Последнее обновление: 2026-08-15.

## Цель проекта

Учиться решать табличные ML-задачи на соревновании Kaggle по предсказанию
зависимости от смартфона. Важно не просто получить score, а до реализации
понимать гипотезу и причину каждого изменения.

## Зафиксированное соглашение

Перед каждым следующим экспериментом:

1. вместе формулируем гипотезу;
2. разбираем, почему она может помочь и чем может навредить;
3. заранее определяем, что именно меняем и как сравниваем;
4. участник явно разрешает реализацию;
5. только после этого меняем код и запускаем обучение.

Ассистент не должен начинать новый `trial-NNN` до обсуждения его гипотезы, плана
проверки и явной команды участника. После нескольких trial принятые улучшения
объединяются в следующий `exp-NNN`. Итоговый exp-коммит создаётся после того, как
участник загрузит submission и сообщит Kaggle score.

## Техническое состояние

- Remote: `origin` указывает на `t1tsl0ver/Predicting_Smartphone_Addiction`.
- Основная ветка: `main`.
- Python: 3.12.10.
- Локальная среда: `.venv`.
- Основной скрипт активной серии: `src/cv_lightgbm.py`.
- Данные: `data/train.csv`, `data/test.csv`, `data/sample_submission.csv`.
- Исторический development holdout: 20%, stratified, seed 42.
- Активный контроль trial: LightGBM/500 с numeric exact-value categories;
  текущий итоговый лидер `exp-003`: до 3000 деревьев, LR 0.01 и early stopping.
  Оба используют 5-fold StratifiedKFold, shuffle, seed 2026.
- Основная метрика: ROC AUC.
- Все скрипты пишут этапы, прогресс итераций, ETA и метрики в консоль и в
  `artifacts/logs/`; частота задаётся CLI-параметрами логирования.
- `src/cv_lightgbm.py` создаёт Kaggle submission только при явно переданном
  `--submission`; обычные trial сохраняют метрики и predictions без лишнего CSV.
- Для Kaggle поддерживается один канонический файл `submission.csv` и метаданные
  `submission.metadata.json`. При явной просьбе создать новый submission эти
  файлы перезаписываются; варианты с суффиксами trial/exp не сохраняются.
